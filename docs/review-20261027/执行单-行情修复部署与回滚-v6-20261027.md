## 0. 影响面（先看这一节）

### 0.1 三条定价通道

| 通道 | 条件 | 可用于成交 | 用户提示 |
|---|---|---|---|
| 上游行情时间 | `quote_time` 可用且 ≤30 分钟 | 是 | 按上游行情时间 HH:MM:SS 定价 |
| 近实时快照 | `quote_time_source=fetch` + 09:30–15:30 + 采集年龄 ≤ 周期+120s（硬上限 40 分钟） | 是 | 按 HH:MM:SS 采集的快照定价；距采集已 N 分钟，**采集后有效期** M 分钟；上游报价时间未知 |
| 当日日线 | ≥15:05 且该日线写入时间 ≥15:00 且不在未来 | 是 | 按 YYYY-MM-DD 收盘价定价 |

三条都不满足 → 拒绝下单，原因码进服务端日志。

> 措辞纪律：**「采集后有效期」不是「报价最大延迟」**。上游若返回缓存旧值，本系统无法感知。

### 0.2 与部署前相比的行为变化

| 场景 | 部署前 | 部署后 |
|---|---|---|
| 盘中，30 分钟内采集过快照 | 报「无法获取当天价格区间」 | **可成交**，回报带 `pricing_notice` |
| 盘中，超过 32 分钟 | 同上 | 拒绝（`snapshot_too_old`） |
| 159865（手工补的那条） | 可下单 | **拒绝**：无 `fetched_at` / `quote_time_source` |
| 收盘后 + 当日日线已入库 | 可下单 | 仍可下单 |
| 持仓估值（展示） | 可能返回 None（盘中） | 回退最近日线并标注「不可用于成交」 |
| 前端下单成功提示 | 仅「下单成功」 | 追加定价说明（**依赖阶段 5 前端发布**） |

## 9. 风险登记

| 风险 | 触发 | 影响 | 处置 |
|---|---|---|---|
| 覆盖挂载源时 inode 变化 | 用 `mv`/编辑器保存 | 容器读旧 inode，改了半天等于没改 | 5.2/5.4 校验 inode |
| 备份被第二次执行覆盖 | 重复运行 | 无法回滚到最初版本 | 0.2 目录非空即停 |
| 重建失败 | 镜像/配置问题 | backend 起不来 | 用 `chain-before.txt` 原链重建，不依赖容器标签 |
| 前端未发版 | `npm ci` 失败 | 用户看不到定价说明 | 明确记为「告知未达成」，不得宣称完成 |
| 供给未启用但日线通道可用 | 18:00 后 | 试单可能成交 | 试单前查当日日线是否存在 |
| 停牌股按昨收成交 | 上游返回昨日快照 | 错误定价 | **未修**，启用供给前必须处理（见第 10 节） |

## 10. 本单明确不做（不得据本单宣称已完成）

1. **停牌识别**：当前无「可信交易状态」，停牌股若上游返回昨日快照，仍会被补上今日 `trade_date`。启用供给前必须补。

3. **`_is_data_fresh` 的 8 小时偏差**：仍是遗留项，与「不完整快照失败续期」是两件事。
4. **ETF 盘中成交**：不支持，且不是「加进股票池」就能解决。
