# 全市场历史同步：离线计划器与恢复边界（2026-10-29）

入口保护已部署；本轮只增加离线开发工具，没有生产连接、部署、出站请求或业务写入。用户确认不知道账户 daily/adj_factor 的权限及额度，继续记为未知。小样成功不是额度证明；禁止通过反复调用直到限额报错来推断额度。

## 已实现的交付物

- `deploy/history_sync_plan.py`：纯标准库计划器，不导入应用、provider、数据库或出站闸门。
- `deploy/plan_tushare_history.py`：读取本地库存观察 JSON，输出候选计划，不执行计划。
- `tests/offline/test_tushare_history_plan.py`：20 项行为测试；offline 全套 237 项通过。

计划冻结去重排序后的候选股票池、Tushare/CN/daily 同源游标和输入观察哈希。最后已有日期包含在增量请求中，保留前复权连续性校验所需重叠。旧契约序列、游标晚于请求结束日、超过当前 30 日通道范围均显式列为 blocked。只要存在阻断，全市场总请求数为 null，不把可处理子集伪装成全市场。

没有历史的股票默认保持旧 worker 的“北京时间当天减 365 天”起点；不会悄悄缩成 30 天。可以显式提供另一个 bootstrap 起点，但这是不同业务范围，不能视为原按钮已恢复。计划的 `execution_authorized` 和 `full_market_ready` 恒为 false。

输入观察由后续只读采集器负责生成，本轮尚未实现该采集器，未对生产全市场生成计划。`contract_verified` 是输入采集器的结论，不是由一个布尔值就证明了生产契约。哈希用于绑定输入与计划，不是真实性签名。真正执行前仍须重新校验索引、整条序列契约和当前内容。

## 可复现的离线输入

下例为合成数据，不是生产证据。`content_sha256` 应来自固定排序、固定序列化的整条同源序列，而非仅最新一条；空集合也须显式采集，不能把查询失败当作空集合。

```json
{
  "symbols": ["600000", "600000.SH"],
  "series": {
    "600000.SH": {
      "data_source": "tushare", "market": "CN", "period": "daily",
      "count": 5, "latest": "2026-10-27", "contract_verified": true,
      "content_sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
    }
  }
}
```

```bash
python3 -B deploy/plan_tushare_history.py /tmp/synthetic-inventory.json \
  --end 2026-10-28 --now 2026-10-29T00:55:00+08:00
python3 -B tests/offline/test_tushare_history_plan.py
```

不提供 quota 时不产生吞吐量估算。若提供 quota，必须显式给出 `daily_requests`、`rolling_minute_requests`、`evidence_ref`，含义是 daily + adj_factor 共享的总预算，不是每个接口各自的额度。计划只计算候选股票所需预算天数下界（每只至少两次请求），不是完成 ETA，也不验证证据来源或创建许可。真实调度仍须逐接口限频、全账户预算与其他调用方隔离。

## 核查出的未闭合实现问题

1. `app/worker/tushare_sync_service.py:2659`：恢复或 force 绕过并发检查；全市场恢复不能沿用此行为。
2. 同文件 `sync_historical_data` 每次重新生成股票池，再按整数 `resume_from_index` 跳过。池顺序/成员变化会让位置失去意义；备用池还使用 set。恢复必须绑定冻结的池和每只股票身份，不能只存位置。
3. 同文件 `_get_last_sync_date` 缺失游标时默认一年。当前手动出口只允许最多 30 天，不能仅把允许股票数从 5 改大。
4. 不能随意将一年 qfq 数据切成独立小窗口再拼接：窗口之间的复权锚点必须一致；跨除权、价格修订仍由历史契约阻断。原五条样本复权因子不变，未验证这一场景。
5. 库中旧 300613 序列应保留并显示阻断。自动补元数据、丢弃旧序列或把跳过标记成成功均不属于本轮授权。

## 下一实现单元：持久化执行与恢复（尚未完成）

- 存储不可变计划和逐标的状态，绑定计划哈希、标的、区间和库存观察哈希；用原子条件更新认领，force 不得绕过锁。
- 请求发出前持久化预算消耗；进程中断后 `in_flight` 为不确定结果，不按“没拿到响应”自动重发。
- 已取数的响应先做契约校验并保存不可变结果及哈希；入库完成且读回核验后才标记 committed。任何状态转换和重启都有故障注入测试。
- 数据已写而提交状态未落盘时，以同源记录内容和冻结结果核对，不重新请求上游；部分批次失败要显示部分完成，不能自动删除成功数据。
- 只有未发送请求的 pending 标的可在新预算窗口继续；许可过期、额度未知、旧序列/复权冲突必须阻断，不能借恢复来续期或清锁。
- 提供只读计划预览与真实用户入口状态，再做受限端到端验收。冻结原入口继续拒绝，不能仅因计划器测试通过而解除阻断。

此文档的恢复机制为待实现要求，不代表已有可运行执行器。真实账户额度仍需账户后台/供应方资料；如无法取得，先设计另行批准的保守有限许可，不承诺全市场完成时间、不放开无限任务。
