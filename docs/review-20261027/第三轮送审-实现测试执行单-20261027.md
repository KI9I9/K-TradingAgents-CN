### 2.1 新增 `app/services/quote_contract.py`（纯标准库）

把「时间/日期/区间」判定收敛成一套，供**写入侧与消费侧共用**，避免两边各写一份。

| 函数 | 职责 |
|---|---|
| `parse_quote_time` | 三态：BSON naive → 按 UTC；ISO 字符串（`Z` / `+08:00` / 无时区）→ 解析，无时区按交易所时区；**其余一律 None** |
| `coerce_trade_date` | `2026-10-27` / `20261027` / `date` / `datetime` → `YYYY-MM-DD` |
| `quote_is_usable` | 校验 `trade_date == 今日` + `updated_at` 在窗口内；解析失败**拒绝** |
| `validate_price_range` | 数值、有限性、`0 < low <= high` |
| `sync_round_skip_reason` | `not_trade_day` / `calendar_unverified` / `pre_open` / `after_close` |
| `build_failure_stats` | 产出 `success=False`，让调度层判 failed |
| `build_quote_doc` | 补 symbol/code、`*_price`→标准名、注入 trade_date、**剔除 None 防止覆盖有效值** |

### 2.2 供给侧（`akshare_sync_service.py`）

1. **时间闸门**：非交易日 / 日历来源为 `fallback` / 09:30 前 / 15:30 后 → 整轮 `skipped`，**一条不写**。
   - 关键：`get_last_trade_date()` 只返回日期、不暴露来源，而「来源是否 fallback」是节假日误判的唯一信号 → 读 Redis 缓存取 `source`（只读，不写）。
2. **空池判失败**：显式 `success=False + error_count+1`。依据：`execute_sync_method` 无条件 `success=True`，`outcome()` 只看 `success is False`。
3. **写入单点**：批量循环、单只保存、`_batch_update_quotes_to_db` 三条路径共用 `build_quote_doc`，`trade_date` 与禁用别名不再各写各的。

### 2.3 消费侧（`paper.py`）

1. `_get_today_price_range`：`market_quotes` 必须「当日 + 未过期」；`etf_daily_quotes` / `stock_daily_quotes` **只认当日**，绝不回退昨日。
2. `_get_last_price` 新增 `strict`：下单路径 `strict=True`；展示路径保持宽松。
3. `current_price` **降级为仅展示**（无行情时间，无法证明新鲜）。
4. 新增当日日K回退，查询只用 `symbol`（实测 `$or` 含 `code` 会扫 5566 条 → 只用 `symbol` 后 `keys=1 / 0ms`）。
5. 文案改为「行情缺失、过期或无效，暂不可下单」，具体原因进日志。

覆盖点（都是**行为断言**，不是源码字符串匹配）：

## 四、请评审重点看的六处

1. **`sync_round_skip_reason` 依赖 `source ∈ {tushare, akshare}`**，source 缺失一律 `calendar_unverified` 整轮跳过。是否过严（Redis 抖动会停发）？还是宁可停发？
2. **读私有方法 `_cal._read_cache()`** 取 `source`：不新增未挂载文件改动的代价是依赖私有 API。可接受，还是有更稳的替代？
3. **`_get_today_price_range` 对 ETF 也要求当日**：`etf_daily_quotes` 由 `etf_sync` 写入，而该任务当前 paused → ETF 指定价单会被拒。是否应给 ETF 单独策略？
4. **`build_quote_doc` 剔除 None**：若上游某字段长期为 None，`market_quotes` 会保留旧值而非被清空——这是「不覆盖有效值」，但也可能让旧值长期存活。是否需要版本号/写入时间戳辅助？
5. **`_get_last_price(strict=True)` 在下单路径彻底不用 `current_price`**：生产该字段 0% 填充，短期无影响；若将来某同步任务回填它，是否会造成「有值但永远用不上」的困惑？
6. **执行单的 R1 顺序陷阱**：新版 `akshare_sync_service.py` import 了 `quote_contract.py`，先删 override 会导致 `ModuleNotFoundError`。执行单已把顺序写死为「先还原 sync 源、再去 override」。请确认这个顺序在你的推演下也成立。
