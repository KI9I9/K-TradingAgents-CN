# 159865 ETF 走势图修复

## 已核实的问题

生产 `etf_daily_quotes` 中 159865 为 0 条。页面先前提交的两次任务仅选择实时行情，并未请求历史；随后历史专用任务 `99a103e8de7a4c39b0eb8263d27e5c25` 也出现“成功但 0 条”。AKShare 1.19.1 的东方财富 ETF 历史接口发生 RemoteDisconnected，旧包装器吞异常并返回空数组，ETF 服务把空数组计为成功，任务协调层也把全失败计为部分成功。

生产新浪历史接口可用，返回 2021-03-08～2026-11-02 的 1371 条日线。修正后的实际解析器已在生产依赖环境验证，最近一年有 242 条，末日收盘 0.520，成交量 273851160 股转换为 2738511.6 手，成交额 141653288 元。实际响应带尾部注释，只解码字符串数据，不执行下载的脚本。

## 修复与交付

- ETF 历史日线保持不复权。东方财富失败或为空时转新浪，限定请求日期范围，核验 OHLC、日期及有限非负成交量/额；记录端点与单位。
- 空返回明确失败，不再报告成功。所有单股同步项均失败时，任务状态改为 failed。
- ETF 详情默认历史，隐藏实时，禁选此入口不支持的 Tushare，并说明价格走势依赖历史数据。A 股入口权限保持不变。
- 不伪造交易状态、最终性或行情时间；历史图表数据不作为恢复日线成交许可的证据。
- 后端替换 stock_sync 的挂载源，新增 etf_sync_service 只读挂载，44→45；原挂载文件不覆盖。前端先加新哈希资源，最后原子替换 index，保留旧资源供已打开的页面使用。
- `deploy/etf_history_delivery.py` 在停机前核验完整 Compose 差异、原容器、源码哈希、数据库和运行许可状态，备份留在生产，隔离容器以 uid1000 导入完整应用。冻结包独立运行，SSH 断开不终止切换。失败恢复原 Compose 链和旧 index，绝不恢复数据库旧快照。
- 保留 Tushare 计划及计数、当日额度避让标记、旧 STOP、封印配置和盘中按需报价许可。不启用 ETF 定时任务，不创建订单，不修改财务同步。

## 验收标准

本地历史规范化、回退及空数据失败回归，以及前端 vue-tsc/Vite 构建通过；上线后必须另以正常鉴权提交一次 159865 AKShare 历史专用任务，确认实际日线非零、日/周/月走势图 API 可读。只有真实入库和接口验收完成才宣布恢复。结果与备份位置待执行后追加。
