用户已要求全市场正常手动同步，并接受限速、断点续跑及异常股票单独报告。此前 600000 单股临时开放脚本未执行，已移除，不能把一次性验收成功当作日常可用。

## 实现

- 原按钮入口对超过 50 只的股票池先创建 running 执行记录，持有统一准入锁，后台核验库存与冻结计划；避免 HTTP 等待数千只库存核验。并发点击仍拒绝。
- 旧契约不明、游标越界、窗口过长的单股冻结为 skipped，零请求、零写入；其他候选股继续。全池均异常仍明确拒绝。
- 只有上游成功响应中的 daily 空表可记为 no_daily_rows；SDK 返回 None、网络失败、上游额度/积分拒绝不能冒充空日线。保留空响应和原库存哈希，零历史写入，可重放核验。
- 前复权重叠价格变化或缺少重叠日：保存响应，单股拒写并报告，不自动迁移原历史数据。请求结果不确定和写入结果不确定仍停止批次。
- 每只股票持久化账本并更新原任务进度。执行器一次载入计划，已提交 payload 验证后仅保留摘要，避免每股重读全市场完整 payload。重新启动后可从既有账本续跑，不重置额度。
- 跳过名单通过现有执行详情的 error_message 展示，结构化结果也保存 skipped_items。partial 表示部分跳过或未完成，不伪报全量成功。
- 新股票默认补齐区间不早于许可 min_date；显式全年模式仍须落在许可日期范围，不自动扩大。
- 增加创业板 302 代码段识别：生产基础表的两条 302132 记录不能当作非 A 股丢弃。
