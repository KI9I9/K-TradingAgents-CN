## 0. 先看这一节：定价策略与影响面

King 2026-10-27 决策：**接受有明确延迟边界的近实时快照用于模拟成交**，但不打开「开关式放行」，不伪造 `quote_time`。落地方式是「把边界写成数据」。

### 0.1 三条定价通道

| 通道 | 触发条件 | 可用于成交 | 用户提示 |
|---|---|---|---|
| **上游行情时间**（`quote_time`） | 上游返回行情时间且 ≤30 分钟 | 是 | 无 |
| **近实时快照**（`quote_time_source=fetch`） | 交易日为今日 + 处于 09:30–15:30 + 采集年龄 ≤ 声明周期+120s（硬上限 40 分钟） | 是 | 「按 HH:MM:SS 采集的快照定价，最大延迟约 N 分钟；非交易所逐笔成交价」 |
| **当日日线**（收盘后） | 15:05 后 + 该日线写入时间 ≥ 当日 15:00 | 是 | 「按当日收盘价定价」 |

三条都不满足 → 拒绝下单，原因码进日志（`quote_time_missing` / `snapshot_too_old` / `outside_snapshot_session` / `snapshot_interval_invalid` / `daily_fallback_before_close` 等）。

### 0.2 参数与刷新频率

| 参数 | 取值 | 来源 |
|---|---|---|
| 快照刷新周期 | **1800 秒（30 分钟）** | `AKSHARE_QUOTES_SYNC_CRON = */30 9-15 * * 1-5`（生产现值）→ 本次随 `config.py` 覆盖改为 `mon-fri`，**周期不变**，仅修星期错位；写入时记入 `snapshot_interval_seconds` |
| 允许延迟 | 周期 + **120 秒**余量 = 1920 秒 | `SNAPSHOT_DELAY_MARGIN_SECONDS` |
| 硬上限 | **2400 秒（40 分钟）** | `MAX_SNAPSHOT_INTERVAL_SECONDS`；声明周期超限直接拒绝，不自动放大 |
| 上游行情时间上限 | 1800 秒 | `DEFAULT_MAX_QUOTE_AGE_SECONDS` |
| 快照可用时段 | 09:30–15:30 | `SESSION_OPEN` / `SNAPSHOT_SESSION_END` |
| 日线回退起点 | 15:05 | `DAILY_FALLBACK_AFTER` |

> 30 分钟是当前 cron 决定的，不是拍脑袋。若将来把 cron 收紧到 6 分钟（`QUOTES_INGEST_ENABLED` 那条链路），同步服务里的 `snapshot_interval_seconds` 要一起改，否则消费侧会按 30 分钟放行、实际却每 6 分钟刷新——边界会失真。

### 0.3 部署后的行为变化（相对现在）

| 场景 | 部署前 | 部署后 |
|---|---|---|
| 盘中下单，有 30 分钟内的快照 | 报「无法获取当天价格区间」 | **可以成交**，回报带 `pricing_notice` |
| 盘中下单，快照超过 32 分钟 | 同上 | 拒绝（`snapshot_too_old`） |
| 盘中下单，快照是昨天写的 | 同上 | 拒绝（`trade_date_mismatch`） |
| 159865（我手工补的那条） | **可以下单** | **仍被拒绝**：该记录没有 `fetched_at` / `quote_time_source`，不是快照写入的 |
| 收盘后 + 当日日线已入库 | 可下单 | 仍可下单（日线通道） |

### 0.4 ETF 覆盖情况（单列，不要和 A 股混为一谈）

- 快照供给的标的池来自 `stock_basic_info`（11154 条），**不含 ETF**（159865 不在该表，已实测）。
- 因此 **ETF 不走近实时快照通道**，盘中没有可成交价。
- ETF 现有数据：`etf_daily_quotes` 仅 **2 个代码 / 247 行**，且 `etf_sync` 任务处于暂停。
- 结论：**ETF 盘中一律不可成交**；收盘后若当日 ETF 日线已入库，才走日线通道。
- 若要让 ETF 也支持盘中，需要单独把 ETF 纳入快照标的池（改 `_get_all_listed_symbols` 的取数范围），属另一轮变更，本单不做。

```bash
M=ta-live-088a60b962bf-mongodb-1
sudo docker exec $M bash -lc 'U=$(cat $MONGO_INITDB_ROOT_USERNAME_FILE); P=$(cat $MONGO_INITDB_ROOT_PASSWORD_FILE); \
  mongosh --quiet "mongodb://$U:$P@127.0.0.1:27017/k_tradingagents?authSource=admin" --eval "
    const q = db.market_quotes.findOne({code:\"600000\"},{_id:0,trade_date:1,fetched_at:1,quote_time_source:1,snapshot_interval_seconds:1});
    printjson(q);
    print(\"today_daily=\" + db.stock_daily_quotes.countDocuments({symbol:\"600000\",period:\"daily\",trade_date:\"<今日 YYYY-MM-DD>\"}));
  "'
```

判定表：

| 快照状态 | 当日日线 | 预期 |
|---|---|---|
| 有 `fetched_at` 且 ≤32 分钟、`trade_date` 为今日、当前在交易时段 | — | **成交**，`pricing_notice` 含「最大延迟约 32 分钟」 |
| 快照缺失 / 过期 / 非今日 | 0 | 拒绝（`snapshot_too_old` / `trade_date_mismatch` / `quote_time_missing`） |
| 快照不可用 | 1（18:00 后） | **成交**，按当日收盘价，`pricing_basis.source=daily_close` |

> 不要写成「供给暂停 ⇒ 试单一定被拒」。快照通道与日线通道是独立的。

## 7. 风险登记

| 风险 | 触发 | 影响 | 处置 |
|---|---|---|---|
| compose 链拼错 | `chain-before.txt` 缺失或含换行 | 重建出错误挂载集 | 4.4 的 `config` 断言会拦住；R1 可秒回 |
| 挂载源未真正覆盖 | 只上传到 staged 未 `cp` | A2 哈希失败 | 4.2 单独一步，带宿主机侧哈希校验 |
| 护栏使盘中不可成交 | 无快照且无当日日线 | 用户看到拒绝 | 先查 `market_quotes` 是否有 32 分钟内的快照；供给未启用时属预期 |
| 快照延迟被用户忽略 | 成交价与真实盘口有差 | 争议 | 回报带 `pricing_notice`，订单存 `pricing_basis`（来源/时间/延迟/上限），可事后追溯 |
| ETF 盘中不可成交 | ETF 不在快照标的池 | 用户看到拒绝 | 已单列说明（§0.4）；要支持需扩标的池，另议 |
| 159865 行为变化 | 手工补的记录无 `fetched_at` | 由可下单变拒绝 | 如实告知，不称「无回归」 |
| 日线回退被误用 | 18:00 后当日日线存在 | 订单按当日收盘价成交 | 属设计内；试单前先查日线是否存在 |
| 日志驱动 none | 用 `docker logs` 判断 | 误以为无异常 | 一律读 `mounts/app_logs/tradingagents.log` |
| 供给 `enabled=true` 残留 | 回滚后重启 | 任务自动恢复运行 | 回滚后显式检查偏好并确认 |
