## 根因与本地修复

`app/core/database.py` 的 `_LoopSafeMongoDatabaseProxy` 每次访问集合都产生新的 `_LoopSafeMongoCollectionProxy`。旧适配器使用 `service.db.stock_daily_quotes != inventory.collection` 比较代理实例，没有比较实际 Mongo 集合，因此即使实际目标相同也拒绝。

`deploy/history_batch_adapters.py` 新增 `same_collection`：相同对象直接通过；否则要求两者解析出的 delegate 都是 PyMongo Collection，使用**同一个客户端实例**且集合相等。不能只比较集合名，也不能只依赖 PyMongo 的客户端相等（相同地址的不同客户端可能相等）。数据库/集合/客户端不同仍拒绝。

验证直接抽取实际 loop-safe 代理类，用真实 Motor/PyMongo 对象验证身份；完整适配器写入用真实代理包装合成存储。恢复旧比较后，测试复现生产的 `service_collection_mismatch`；修复后通过。未连接生产数据库执行这些测试。

另修复验收工具自身的输出协议：应用导入会输出日志，原控制器对整个 stdout 做 JSON 解析，错误地报告 `failed_unknown_outcome`，STOP 检查也被日志干扰。实际容器内结果和 STOP 均存在。新工具使用显式结果前缀，保留私有原始 stdout；停止确认取最后一行。原始失败记录不覆盖，以只读结果复核为准。
