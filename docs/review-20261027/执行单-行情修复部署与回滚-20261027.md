## 5. 回滚

### ⚠️ 顺序陷阱（务必先读）

`akshare_sync_service.py` 新版 **import 了** `quote_contract.py`。
如果**先删 override**（`quote_contract.py` 随挂载消失、`paper.py` 回到镜像版），而后改的 `akshare_sync_service.py` 仍在，
→ 启动即 `ModuleNotFoundError: app.services.quote_contract` → backend 起不来。

**正确顺序永远是：先还原 `akshare_sync_service.py` 的挂载源，再移除 override。**
两步合并成一次重启，最终状态完全一致（旧 paper.py + 旧 sync + 无 quote_contract）。

### R1 完整回退（推荐，一次重启，约 60 秒）

```bash
B=$(ls -d /home/ubuntu/k-tradingagents-paper-guard-20261027-v1/backup-* | tail -1)
C=ta-live-088a60b962bf-backend-1

# ① 还原供给侧挂载源（原地覆盖，不要 mv —— 换 inode 容器仍挂旧 inode）
sudo cp -a $B/akshare_sync_service.py \
  /home/ubuntu/k-tradingagents-akshare-batch-20261023-v1/app/worker/akshare_sync_service.py

# ② 去掉 override 重建（挂载数回到 21）
CHAIN=$(sudo docker inspect $C --format '{{index .Config.Labels "com.docker.compose.project.config_files"}}')
CHAIN_OLD=$(echo "$CHAIN" | tr ',' '\n' | grep -v 'compose.paper-guard.json' | paste -sd, -)
cd /home/ubuntu/k-tradingagents-migration-receiver-20261016/final-launch-20261018-v1
sudo docker compose --project-name ta-live-088a60b962bf --profile cutover-approved \
  $(printf ' -f %s' $(echo "$CHAIN_OLD" | tr ',' ' ')) \
  up -d --no-deps --force-recreate backend
```

### R2 只回退供给侧（保留护栏）

适合「护栏没问题、但供给写坏了」：

```bash
B=$(ls -d /home/ubuntu/k-tradingagents-paper-guard-20261027-v1/backup-* | tail -1)
sudo cp -a $B/akshare_sync_service.py \
  /home/ubuntu/k-tradingagents-akshare-batch-20261023-v1/app/worker/akshare_sync_service.py
sudo docker restart ta-live-088a60b962bf-backend-1
```
此时 `quote_contract.py` 仍挂载、`paper.py` 仍是新版，一致可用。

## 6. 风险登记

| 风险 | 触发条件 | 影响 | 处置 |
|---|---|---|---|
| compose 链拼错 | `CHAIN` 解析失败或漏文件 | 重建出错误的挂载集 | 重建前先 `echo` 出完整命令**人工核对**；R1 可秒回 |
| 新挂载源不存在 | 忘放文件 | `create_host_path:false` 直接失败，容器起不来 | 这是**故意**的：宁可失败也不静默建空文件。按 R1 回滚 |
| 护栏过严导致「完全不能下单」 | 供给未启用 | 用户看到拒绝文案 | 预期行为；启用供给后恢复。若希望先保留旧行为，可**只覆盖 `akshare_sync_service.py` 的挂载源**（不新增挂载、不动 `paper.py`） |
| `sync_round_skip_reason` 要求 `source ∈ {tushare, akshare}` | Redis 缓存不可用 | 供给侧**整轮跳过**（`calendar_unverified`） | 保守方向，不会写脏数据；日志会明确打出该原因，按提示查缓存 |
| 重启窗口内下单 | 30~60 秒 | 502 | 建议在非交易时段执行（15:30 后） |
| 挂载数变化 | 21→23 | parity 脚本、巡检断言失效 | 同步更新 `PRODUCTION_PARITY.md` 与巡检阈值 |
