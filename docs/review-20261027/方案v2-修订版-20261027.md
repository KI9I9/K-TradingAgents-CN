## 3. 修正后的根因模型

```
下单报「无法获取股票 X 的当天价格区间」
    │
    ├─ 直接原因：market_quotes 缺 high/low（指定价）或 close（市价）
    │
    └─ 为什么缺？五层叠加，按影响排序
         │
         ├─【第 1 层 · 新发现 · 决定性】行情字段契约错误
         │    provider 批量分支只输出 *_price，写入侧 $set 直接落库
         │    → 新记录缺 high/low/close；旧记录残留昨日值
         │    → 即使开关全开，修复也无效（甚至更危险：按昨日区间成交）
         │
         ├─【第 2 层】数据库偏好 akshare_quotes_sync.enabled=false
         │    restore_preferences 按 DB 覆盖启动期状态（运行期唯一开关）
         │
         ├─【第 3 层】代码标的查询恒空
         │    akshare_sync_service.py:434 用 {"list_status":"L"}，该字段不存在
         │
         ├─【第 4 层】cron 星期错位
         │    "1-5" 在 APScheduler 是周二~周六，周一不触发
         │
         └─【第 5 层 · 待验证】新鲜度判断可能失效
              UTC+8 硬编码 + 负差值当新鲜 → 若有旧记录则永久跳过同步
              （仅在主机时区为 UTC 时触发，需实地确认）
```

**修正表述**：第 2 层能覆盖第 1 层的启动期暂停（环境变量），所以「四层缺一不可」是错的。准确说法是：**必须满足 ①字段契约正确 ②DB 偏好为 true ③标的池非空 ④cron 正确；第 5 层需单独确认**。

#### 关键设计决策

**① `trade_date` 不在 provider 设置**

快照接口（`stock_zh_a_spot` / `stock_zh_a_spot_em`）**不返回行情所属日期**。若在 provider 用 `datetime.now()` 填，盘前或非交易日会把伪数据标成当日——正是评审警告的问题。故交由写入侧按交易日历解析：

```python
if await _cal.is_today_trade_day() and _now_cst.time() >= time(9, 30):
    resolved_trade_date = _now_cst.strftime("%Y-%m-%d")   # 已开盘，属于当日
else:
    resolved_trade_date = await _cal.get_last_trade_date() # 盘前/非交易日，退回最近交易日
```

解析失败时不注入，保留库内原值，并在日志留 warning。

**② 不切换 `return_all=True`**

评审已指出它会改变目标筛选语义（`codes` 参数失效）并把「当前日期」直接当交易日期。故只补字段，不动筛选路径。

**③ `updated_at` 用 `+08:00` 显式时区**

`_is_data_fresh` 对 `tzinfo == timezone.utc` 有硬编码 `+8` 分支，而其他时区走 `astimezone()` 正确转换。输出 `+08:00` 可绕开该缺陷分支（`TestFreshnessNegativeDelta.test_plus8_timestamp_is_handled_correctly` 已验证）。**这是规避，不是根治**，第 5 层缺陷本身未修（见第 10 节）。

**④ 未修改 `paper.py`**

按约束不动价格校验逻辑。

## 7. 验收标准（修订）

替换 v1.1 的「条数接近 5,567 + 随机 20 条 + 下单不报错」：

| 维度 | 判定 |
|---|---|
| 字段一致性 | `market_quotes` 当日记录**全部**含 `open/high/low/close` 且 `high >= low > 0`；抽查与上游原始行逐条比对 |
| 行情时间真实性 | `trade_date` 与 `updated_at` 自洽；非交易日/盘前运行不得产生当日 `trade_date` |
| 分市场覆盖 | 沪 / 深 / 北**分别**统计目标池、上游返回、有效入库三者差集；不只看总数 |
| 失败清单 | 未返回标的逐个列出并分类（停牌 / 上游缺失 / 代码非法），不得计入成功 |
| 旧值残留 | 取一只昨日有快照的标的，确认同步后 `high/low/close/trade_date` 全部更新为当日 |
| 试单 | 用**专用测试账户**，指定价与市价各一笔；核对成交价、手续费、持仓成本 |

## 8. 回滚顺序（修订）

评审指出 v1.1 的回滚不完整，修正为：

```
1. POST /api/scheduler/jobs/akshare_quotes_sync/pause     ← 先停调度
2. 确认在途执行已结束或被取消（pause 不会终止正在运行的任务）
3. 恢复全部关联挂载源文件（cp 回 .bak-20261027，保 inode）
4. docker restart <实际容器名>
5. 容器内 sha256 复验，确认回到旧版本
6. 注意：文件回滚不会清除 DB 中的 enabled=true —— 需显式再执行一次 pause，
   或不 resume 即可；不要用「直接改 DB 置 false」替代服务层操作
```

**不可回滚的部分**：已成交的订单、账户资金变化、持仓成本。这正是取消阶段 A 的核心理由之一。
