# 历史库存与异步适配器验收（2026-10-29）

本轮只完成本机开发和测试，未连接生产、未访问 Tushare、未写生产库。生产入口仍明确拒绝全市场同步。不是可部署的全市场开放包。

## 实现

新增 `deploy/history_batch_adapters.py`：

- `Inventory` 接收已有 collection 和显式候选股票池，不建立数据库连接、不创建索引、不初始化 provider。池去重并固定排序，逐只读取 `symbol + data_source=tushare + period=daily`，不能借 AKShare 最新日推进 Tushare 游标。
- 每条序列最多 20,000 行、单查询最多 10 秒；完整唯一索引为硬前提。查询错误不当作空集合。旧契约标记为不可用，坏日期/重复日期直接失败。
- 观察包含完整序列的规范 BSON JSON 哈希（包括 ID 和时间戳）；空集合也有显式观察。它不是全库原子快照，执行前逐只再次比对。尚未实现自动从 `stock_basic_info` 选择并审核全市场股票池。
- `HistoricalAdapter` 在现有 ManualJob 类许可上下文中调用 provider factory 和真实 `get_historical_data` 接口，强制许可标的/日期与冻结任务完全一致。没有许可创建、续期、计数重置或 STOP 删除逻辑。
- 用真实 `tushare_documents` 验证 frame；以严格 JSON 冻结 frame 和标准化 documents，重建后逐字段验证不变。不使用 pickle；不重新推导成交量或复权价格。
- 写入前校验库存、旧序列契约、服务实际数据库与库存采集目标一致，然后复用真实 `HistoricalDataService.save_historical_data`。新入库数必须吻合。
- 恢复核验覆盖目标业务内容、完整日期集合、区间外旧记录，以及相同重放记录的 ID/时间戳。多一条、少一条、金额错误、区间外改动均不能当作完成。

`history_batch_journal.py` 增加 `advance_async`；同步 `advance` 保留供本地调用。provider、Motor 和存储方法均留在调用者事件循环，不另建线程池/跨循环访问数据库。原 28 项故障测试继续通过。

## 请求预算与授权边界

适配器接受调用方显式提供的 `authorize` 与 `job_factory`，仍无生产执行 CLI、路由或调度挂接。

- `authorize` 分别检查 fetch/write/reconcile，取数许可不自动授权正式写库。
- 逐次 HTTP 请求继续由现有 ManualJob.perform 先持久化计数再调用发送操作；批次 `fetch_attempts` 不能代替 HTTP 账本。
- 完成取数调用 `job.finish()`，必须已计入 daily 和 adj_factor 两次。只做 daily 却返回 frame，会被拒绝完成。
- 当前旧手动策略的额度/期限/STOP **没有改变**。测试使用私有临时目录和历史合成时钟，不能视为生产许可。
- **新发现的交付阻断**：旧 `DailyGate.begin` 按调用当天生成日期。跨日恢复的固定计划不能直接复用它；适配器会因 scope mismatch 拒绝，而不是改计划或扩大许可。必须另行实现绑定计划、固定区间和有限预算的新许可机制，保留旧锁存证据。
- 用户不知道账户实际额度；这不等于无限额度，也不构成新上游采样授权。
