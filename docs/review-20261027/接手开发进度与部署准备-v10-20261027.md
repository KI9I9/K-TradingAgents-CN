## 生产执行顺序（需补齐证据并单独授权后封版）

1. **先完成本地前端构建**。保留依赖锁文件、源码哈希、构建日志和 dist 包哈希；类型检查或构建失败即阻断。
   不以 `npx vite build` 绕过 `npm run build`。不把基线既有错误混称为此次改动引入。
2. **准备凭据与授权**。运维会话 Token 由运维安全注入进程环境，不写仓库、不回显，不要求在聊天中粘贴。
   生产重启、任务操作及真实行情源调用分别遵守授权范围；本轮仅准备关闭写入的部署。
3. **传输到全新的暂存目录**。使用交接中指定的 SSH config 与主机别名，不能使用不存在的 `osaka`。
   验证包哈希、相对路径 SHA256SUMS、manifest、前端包；不要修改现有挂载源。
4. **取得运行证据**。保存 backend/frontend inspect、原始 Compose 链和合并配置，核对固定镜像 ID、
   全部现有挂载、9 个文件的基线哈希和写闸环境值。输出中不包含密钥或完整环境变量值。
   使用 `--project-directory`，不尝试普通用户 cd 到 root:700 目录。
5. **验证调度及偏好**。API 必须成功，目标任务必须暂停且无在途执行；查询持久化偏好并验证 JSON。
   `quotes_ingestion_service` 若不存在，还需有效配置证明不会在重启时注册启用。
   缺失偏好不能直接当作 false，必须与已核验的启动默认配置共同判断。
   任何暂停操作都属于生产变更，不用“预检”名义自动执行。
6. **预先生成并校验前后端合并配置**。只允许 manifest 指定的新增挂载，现有服务配置不变。
   前端 override 的目标为 `/usr/share/nginx/html`，只读；记录完整原链作为独立回滚输入。
7. **进入维护窗口，先停止 backend 并确认退出**。阻止手动入口和进程内写入；同时确认没有其他已识别写入进程。
   停止后再次核验持久化偏好，随后采集行情价格/契约元数据快照，避免把停机前并发更新当作部署副作用。
8. **备份、覆盖、重建**。备份目录非空即停，记录原 inode 与哈希；原地 cp 3 个源文件后自动逐项比较。
   使用完整原链、指定 profile、`--no-deps --force-recreate`，仅重建相应服务；前端要有真实安装与重建步骤。
   覆盖开始后的任何失败都进入已审核回滚分支，不能仅退出留下半套版本。
9. **验收**。核对 9 个运行文件哈希、实际模块路径、写闸关闭、健康状态、真实调度状态、快照内容和前端资源。
   容器内冒烟使用导出的同一脚本，例如从宿主机以 `docker exec -i … python3 -B - --installed` 输入脚本；
   退出码必须为 0。浏览器 CN/ETF 下单预期拒绝，展示估值继续可用。不声称所有市场都停止交易。
10. **故障回滚**。先停止故障 backend，验证 `.State.Running=false`；核验当前持久化偏好与基线启动配置
    确实不会恢复自动行情写入后，才恢复 3 个源文件并用原链重建。无法证明就保持停止，不能“先重建再 pause”。
    前端用保存的原始完整链独立回滚。验证的是恢复后目标源文件哈希，不是备份文件自己的哈希。
    回滚恢复的是基线行为，会撤掉本次护栏，不能宣称仍保持本次的全面写入隔离。

## v9 已确认不能照抄的点

- 漏发三个写闸模块；只部署 v9 的 6 个后端文件不等于运行全部仓库修复。
- `scp ... osaka:/tmp/` 与交接声明的别名不符。
- 偏好查询的 `mongosh` 与 `--eval` 分两行且没有续行符；`--eval` 会成为另一条 shell 命令。
- 冒烟缺少必需的 `now` 参数，已离线复现 TypeError。
- 没有安装前端 dist、生成前端 override、重建 frontend 的步骤，却验收挂载数为 5。
- 故障分支仍允许先重建后检查偏好，与前文原则冲突。
- stdin 交互式 mongosh 输出可能带提示符；最终执行单应采用明确非交互的查询方式并解析 JSON，不能仅比较输出大小。
