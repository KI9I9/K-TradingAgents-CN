## 实现

只修改/新增四个应用文件：

| 文件 | 行为 |
|---|---|
| `app/services/historical_contract.py`（新） | 明确 Tushare 原始单位与来源；完整验证批次；旧契约和前复权连续性检查 |
| `app/services/historical_data_service.py` | Tushare 专用严格保存分支；其它来源保留原处理；检查唯一索引；确认写入结果并向上传递错误 |
| `app/worker/tushare_sync_service.py` | 同源同周期游标、北京时间截止时刻、空池/部分失败结果、出站前旧序列预检 |
| `tradingagents/dataflows/providers/china/tushare.py` | 历史取数标记真实入口、单位、请求范围及复权模式；拒绝非法周期与 ETF 非日线冒充 |

- 股票历史仍走 `pro_bar(adj='qfq')`，不改为不复权。ETF 的 `fund_daily` 明确为未复权日线；本次不启用 ETF 同步。
- 输入成交量为手，落库仍为手；成交额从千元转元。直接构造新记录，不修改传入 DataFrame，重复使用不会重复换算。
- 元数据来自实际调用入口，`volume_unit=lot`、`amount_unit=CNY`、`price_adjustment`、`history_contract_version=1` 落库。
  不新增 `is_final`、`final_state` 或 `trading_status`，不把收盘时刻当作最终性证据。
- 日期必须真实存在、在请求区间内、不得重复或未来；缺失日期不落到“今天”。代码/周期/字段别名冲突、非法 OHLC、缺失成交量、非有限数均拒绝。
  成交量/成交额的零值保留；缺失成交额保留 None，不补零。
- 一只股票整个输入批次先验证再写。`matched + upserted` 用于确认处理数量；修改数为零不代表失败。
  完全相同的重放不更新业务记录及时间戳；`overwrite=False` 保留已存在的记录。
- 唯一索引缺失、数据库错误、不确认写入都会失败。部分批次写入不是事务：中途故障可能留下已成功前缀，明确报失败；重放按唯一键补齐。
- 现有同源同周期记录没有新契约时拒绝自动追加/迁移，并在调用历史 provider 前预检，避免明知无法保存仍消耗请求。
  其它来源的正常历史记录不会因此被改写或阻断。
- 增量查询按 `symbol + data_source + period`，重取最后一根作为重叠校验。前复权重叠 OHLC 改变或追加缺少重叠时拒绝拼接。
  这会阻止除权或上游修订后的自动拼接，需要另行核验该股票序列；不会自动全量重刷。
- 无游标时增量默认窗口限制为最近一年，不再隐式回刷至上市日/1990年；数据库游标读取失败不退回更大范围取数。
- 18:00 截止按北京时间；显式同步前一日可在盘前执行；当日增量在 18:00 前仍跳过。定时、手动、强制入口都不能绕过 STOP。
- 零写入、空池及部分失败如实失败；不再用 80% 成功率将整轮标成成功。调度包装器检查实际业务 success，而不只相信线程池返回。
- Tushare 实时快照转历史的旁路没有历史接口来源证据，会被严格保存分支拒绝。本轮不为此伪造 metadata，不应启用实时小时任务。
