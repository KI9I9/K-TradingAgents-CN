五、硬规则（违反会出事）
====================================================================

1. compose 必须带 --profile cutover-approved；重建用 --no-deps --force-recreate <service>
2. compose 工作目录 .../final-launch-20261018-v1 是 root:root 700，普通用户 cd 会被拒绝
   → 一律用 --project-directory，不要 cd
3. 改挂载源必须原地 cp，不能 mv / 不能用编辑器保存（换 inode，容器还读旧文件）
4. runtime-config.json 被 launch-context.json 的 SHA256 封印，改一个字节容器静默退出
5. 日志驱动是 none，docker logs 永远是空的；只能读
   /home/ubuntu/k-tradingagents-migration-receiver-20261016/final-restore-20261018-v2/mounts/app_logs/tradingagents.log
6. paper.py / quote_contract.py / stock_sync.py 都不在现有挂载里
   → 改仓库文件不生效，必须新增挂载 + 重建容器
7. 不读、不回显任何密钥；需要时只给空值模板
