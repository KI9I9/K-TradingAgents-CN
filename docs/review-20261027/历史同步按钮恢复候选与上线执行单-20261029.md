# 原“历史数据同步（Tushare）”按钮恢复候选（2026-10-29）

## 本次修复的是用户入口

原按钮调用 `/api/scheduler/jobs/tushare_historical_sync/trigger`，此前在 `SchedulerService.trigger_job` 被无条件 HTTP 400 拦截。本次只把这个历史任务接到 `HistoryBatchService`，其他 Tushare 任务仍拒绝。前端保持原按钮和现有任务列表，不新增另一个代替品。

用户点击后：校验单独的有限许可 → 固定计划 → 写入现有 scheduler_executions → 后台 provider 取 daily/adj_factor → 原历史契约与存储服务 → 读回核验 → 在现有列表显示成功/部分完成/失败。任务显示授权范围内的股票数和结束日期；不得把有限股票验收称为全市场恢复。

已完成的行为：

- 普通按钮可以走通完整链路；force 不能绕锁，非管理员不能触发。
- 缺历史数据时支持原有一年初始化，新增出口最多 366 个日历日/366 条响应；不切分成不同复权锚点的 30 日块。
- 许可绑定具体计划、股票与固定日期；跨日继续已保存结果不会把区间偷偷改成当天。
- 同日同模式重复点击先只读核验已完成数据，不重新请求或扣额度。数据漂移明确拒绝。
- 请求预算在每次 HTTP 发送前落盘，有限总预算与每日/分钟预算分别检查；未知账户额度不能用本地预算冒充。
- 旧契约和复权冲突在请求前/写入前拒绝并列出标的，保留旧数据，不自动迁移。当前全市场池中已知旧 300613 序列仍需显式处置，不能称为所有股票无阻断。

新许可目录为 `/app/runtime/tushare-history-batch-v1`。HTTP 不创建许可、不续期、不重置账本；旧全局/手动/采样 STOP 与计数保留。尚未在生产创建新许可或部署此版本。
