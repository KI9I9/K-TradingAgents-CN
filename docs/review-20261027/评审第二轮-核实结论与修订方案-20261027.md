### 我自己复核出的两条硬证据（比评审更具体）

**① 我拟的日线回退查询会全分区扫描**

```
$or:[{symbol},{code}] + period + trade_date  →  nReturned=1  docsExamined=5566  keys=5566  ms=8
仅 {symbol, period, trade_date}              →  nReturned=1  docsExamined=1     keys=1     ms=0
```

`stock_daily_quotes` 的索引是 `(symbol, trade_date, data_source, period)` 唯一索引 + `symbol` + `trade_date` + `(symbol, trade_date)`，**没有 `code` 索引**。`$or` 里的 `code` 分支走不了索引，把当日整个分区 5566 条全捞出来。评审只质疑「keys=1 不能证明 $or 高效」，实测是 **5566 倍**。→ 回退查询必须只用 `symbol`。

**② 15:05 已收盘，`stock_daily_quotes` 今日仍 0 行**

```
today rows = 0 ；latest = "2026-10-26"
```

说明日线确实只在 18:00 批量写入，盘中不存在当日日线（正常路径）。但这只证明「当前没有别的写入者」，不能证明未来不会有（例如请求时 kline 落库）——评审要求「排除其他写入路径」仍然成立。
