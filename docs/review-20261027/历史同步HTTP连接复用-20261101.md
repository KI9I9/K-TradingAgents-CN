## 要解决的实现问题

现有`MainlandTransport._send`每次创建新Unix/TLS连接并请求Connection: close。每只股票重新创建provider/client，故仅在client对象内缓存也无法减少跨股票的TLS握手。跨境SSH路径间歇重传会重复放大该成本。网络本身尚未修复，连接复用只能减少握手次数，不能保证长连接不再中断。

本机对固定上游首页的两次无凭据HEAD均为HTTP/1.1 200、keep-alive，同一连接约0.126/0.028秒。首页结果不证明/dataapi/daily一定支持复用；实现只对实际完整响应允许复用，服务端要求关闭时仍关闭。

## 实现与边界

- `app/services/tushare_history_batches.py::HistoryBatchService._run`为单个后台历史任务建立连接作用域；通过ContextVar随asyncio.to_thread传播，与逐股授权对象分离。
- `tradingagents/utils/tushare_egress.py`在作用域内仅缓存一个完整读取、HTTP/1.1且允许持久连接的成功响应连接。按Token和timeout分隔；空闲5秒、连接年龄120秒或64次请求后更换；检测到EOF/待读字节先丢弃。任务结束、异常或取消会关闭缓存与活动连接。传输层不重试、不重连已发送请求，不修改既有有账本的超时重试策略。
- 每个query仍在`job.perform`或原Permit.perform内记账和检查STOP/额度/期限，之后才取得连接；缓存不产生授权。默认未进入历史任务作用域的调用继续使用Connection: close。
- 每个HTTP尝试单独维持原30秒总期限，计时器带代号，防止旧回调误关后续请求。另修正`HTTPConnection.getresponse`处理Connection: close时提前调用close导致响应体读取失去总计时的问题；响应文件仍需读取，不能在收到header时shutdown，也不能提前取消watchdog。
- 固定Unix socket、上游、CA/主机名验证、许可、请求范围、写入契约和所有STOP保持原样。失效连接在检查后、真正发送前关闭仍可能造成请求失败；该竞态不允许隐藏重发。
