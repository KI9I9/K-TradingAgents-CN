# `TA_TOKEN` 从哪来

> 结论先说：**没有现成的 `TA_TOKEN` 存在某个配置里**。它是我在执行单里给「运维用 Bearer Token」起的占位名，
> 真实身份是 **登录接口签发的 JWT**，有效期 **1 小时**。

## 1. 它到底是什么（已核对代码）

```
app/routers/scheduler.py:155   @router.get("/jobs")
                               user: dict = Depends(get_current_user)
app/routers/auth_db.py:70      get_current_user 支持三种：京东云 Basic / JWT Bearer / Session Cookie
app/routers/auth_db.py:340     token = AuthService.create_access_token(sub=user.username, session_id=...)
app/router_registry.py:85      auth 路由挂载在 /api/auth
```

- 走的是 **JWT Bearer**（`Authorization: Bearer <token>`），不是 API Key。
- token 里带 `session_id`，服务端还会去 MongoDB `sessions` 集合校验；**1 小时 TTL**（refresh 7 天）。
- 所以拿不到一个「长期有效」的静态 token，也不该造一个。

生产账号情况（只读核实）：`users` 集合 **1 条**，`is_admin=true`，`is_active`。代码里**没有注册接口**，不能新建账号。

## 2. 三种拿法，按推荐顺序

### A. King 给凭据、接手方自己登录（推荐）

King 在 devbox 上建一个只读凭据文件（**不要贴进聊天、不要进 git**）：

```bash
umask 077 && printf '%s\n%s\n' '用户名' '密码' > ~/.ta_ops_cred && chmod 600 ~/.ta_ops_cred
```

接手方换 token（不打印密码与 token）：

```bash
C=ta-live-088a60b962bf-backend-1
U=$(sed -n 1p ~/.ta_ops_cred); P=$(sed -n 2p ~/.ta_ops_cred)
umask 077
printf '{"username":"%s","password":"%s"}' "$U" "$P" > /tmp/login_req.json
sudo docker exec -i $C curl -s -X POST http://127.0.0.1:8000/api/auth/login \
  -H 'Content-Type: application/json' --data-binary @- < /tmp/login_req.json > /tmp/login.json
rm -f /tmp/login_req.json
python3 -c "import json;d=json.load(open('/tmp/login.json'));print('ok' if d.get('data',{}).get('access_token') else 'FAIL')"
```

用法（token 只放文件，不进命令行参数，避免 `ps` 里被看到）：

```bash
python3 -c "import json;print('header = \"Authorization: Bearer '+json.load(open('/tmp/login.json'))['data']['access_token']+'\"')" > /tmp/curlrc
sudo docker exec $C curl -sf -K /tmp/curlrc http://127.0.0.1:8000/api/scheduler/jobs | head -c 300
```

有效期 1 小时。过期重跑上面那段即可（部署窗口内一般一次够用）。

### B. King 自己登录浏览器，把 token 复制给接手方

登录前端 → 开发者工具 → `localStorage` 里取 `access_token`（或直接取 Cookie）。
**缺点**：token 会经过聊天/文档，且 1 小时就失效，容易出现「刚贴过去就过期」。除非 A 不可行，不建议。

### C. 只在部署时由 King 跑那两条命令

需要 token 的只有两处：执行单 **4.4**（部署前看任务状态）和 **A7**（部署后核对仍暂停）。
King 可以自己在部署窗口内跑，把**输出**（不含 token）交给接手方。这样谁都不用把凭据交出去，代价是 King 必须在线。

## 3. 注意事项

- **登录会写一条审计**：`operation_logs` 会记录这次登录（含 IP）。这是应用正常行为，不是我们额外写库。
- 拿不到的后果：**必须停**。不要用「启动日志里有 `⏸️ ... 已添加但暂停`」替代——
  `app/main.py` 在打印暂停之后还会恢复持久化偏好，日志证明不了最终状态（这条已被评审否掉过一次）。
- 不要走的路：用 `settings.JWT_SECRET` 自己签一个。那等于绕过认证，而且还要往 `sessions` 写记录，评审不会接受。
- 不要在任何文档、提交、截图中出现 token 或密码明文。

## 4. 执行单里怎么改

执行单 v9 的 `: "${TA_TOKEN:?需要运维 Bearer Token}"` 保持不变，但含义改为
「一个 1 小时内有效的 JWT」，按上面 A/B/C 任一方式取得后导出为该变量即可。
