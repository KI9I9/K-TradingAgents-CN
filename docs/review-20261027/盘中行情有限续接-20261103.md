## 实现与交付范围

`app/services/paper_quote_supply.py::read_permit` 保留 version 1 的 24 小时上限；
新增 version 2，最长 7 天，并要求 `renewal_of_sha256` 指向被替换的许可。
该字段用于运维追溯，不是数字签名；写许可的权限仍由受控的生产文件权限提供。
读取许可不会续期，未安装 version 2 时原许可的期限和行为不变。

`deploy/renew_paper_quote_supply.py` 只接受明确的绝对到期时间、旧许可精确哈希，
要求旧许可仍有效且新期限更晚。先备份旧许可及保护状态，再原子替换；
用正常鉴权读取 600000 和 159865 的报价 API，复用已有的同源价格/时间/状态验收。
不创建订单、不写行情表，不调用 Tushare。报价或保护状态验收失败则恢复原许可字节；
若发现未知替换则保留现场，不覆盖第三方改动。原许可恢复后仍在原时间到期。

`deploy/paper_supply_continuity.py` 及对应 launcher 使用冻结的一次性 detached controller：

1. 比对 45 挂载、镜像/容器 ID、完整运行配置、已有应用文件和原许可；原始完整配置留在生产。
2. 备份原源码、配置、许可、运行账本及保护集合；核实无正在运行的同步任务。
3. 以实际容器用户在无网络、无生产环境变量/凭据/运行卷的隔离容器里导入完整应用。
   独立进程检查候选 reader 和续期前置条件，不修改运行应用或续期。
4. 获授权后，仅在连续交易时段且距收盘有足够余量时停止 backend，原地覆盖已有挂载源文件，
   保留 inode/模式，再启动同一容器。挂载维持 45，不改 Compose、镜像或前端。
5. 确认保护状态不变，再续期并读取报价 API 验收。前置或源码交付失败恢复原源码；
   即使新应用启动失败，也能从已核验的 runtime 宿主挂载读取旧许可后回滚，无需在停止的容器里 exec。

如果续期结果不确定或发现新许可仍存在，控制器不会盲目恢复旧 reader（旧 reader 不支持 v2），
而是保留新版代码和现场、报告 `rollback_requires_attention`。管理连接断开只查询 status，
不重复 execute。恢复业务数据不属于回滚步骤。
