# Tushare 状态、限制与恢复原则

## 当前定位

Tushare 只保留受限历史日线通道。账户积分维持 140；这不是本地许可额度的同义词。供应方权限、接口窗口、分钟/日额度和网络转发都可能先于本地预算停止任务。

历史计划曾使用原 5,577 只非复权日线增量，计划日期和预算由当次授权固定。执行因 `usage_limit`、`timeout`、`tls_failed` 或 `network_failed` 停止的，都必须保留原执行证据和 STOP。不能把“按钮返回成功”“任务已提交”“TLS 偶尔握手成功”当作全市场完成。

## 闸门和禁止动作

- Tushare 全局 STOP 是硬安全边界；除非有新的、明确范围和期限的授权及完整备份，不得删除。
- 不启用 Tushare 实时行情任务，不打开财务/基础数据全市场任务，不绕过出口转发。
- 不重置已用请求数、不把未确认请求归零、不删除 `fetching` 账本、不新建代际掩盖旧断点。
- 恢复只能复用原计划和未完成股票，先全量备份并按 `_id`/原始 BSON 对账，再解除该代际 STOP。
- 失败即停，结果不确定时只查询 `status`，绝不重发 execute。

## 140 积分意味着什么

140 积分并不能推出 `daily`、`adj_factor`、财务接口或实时接口的具体额度。额度必须以供应方账户页面或明确的官方权限说明为准。不要为了“测试连接”额外请求上游；每一次请求可能计费或触发限额。

## 恢复前证据

至少需要：

1. 当前 generation、计划哈希、STOP 原因和累计/当日计数；
2. 所有已完成结果及未完成股票库存；
3. 相关非复权/复权集合的完整 BSON/索引哈希；
4. 调度许可、任务偏好、转发服务状态和三次 TLS 证书校验；
5. 明确的日期边界、标的池、API 白名单、请求预算和到期时间。

恢复执行后需核对：原记录逐字节保持、只改变允许的断点状态、请求计数单调增加、数据契约（volume=lot、amount=CNY）正确、STOP 只在证据持久化后解除。

## UI 解释

出现“历史同步已停止，请核查执行记录 [disabled]”或“上游请求连续超时 [timeout]”时，`disabled`/`timeout` 是保护性状态，不是让用户再次点击即可解决的普通错误。先查看执行详情、停止原因、计划和断点，再决定是否准备新的受限恢复包。

## 与 AKShare 的关系

AKShare 历史同步可以独立运行；不要因为 AKShare 正常就解除 Tushare STOP，也不要把 AKShare 财务任务的成功当成 Tushare 日线或实时接口权限证明。
