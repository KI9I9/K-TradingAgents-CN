# 部署、验收、回滚与连接故障手册

## 0. 总原则

任何生产写操作都必须先有：明确范围和期限的授权、冻结包哈希、即时只读预检、持久化备份、隔离导入/静态校验和可执行回滚。SSH 回执不明时只能查询状态，不能重复发送原子 execute。

所有涉及容器、环境、compose、systemd 或生产配置的命令先在本机脱敏：

```bash
python3 /home/ubuntu/.local/bin/safe-inspect.py cmd <原命令及参数>
python3 /home/ubuntu/.local/bin/safe-inspect.py file <文件路径>
<命令> | python3 /home/ubuntu/.local/bin/safe-inspect.py stdin
```

禁止直接输出 `.env`、compose、`docker inspect`、`env`、私钥、Token 或秘密目录。

## 2. 盘中行情切换原则

- 许可安排工具只允许在非交易时段运行；它不重启、不请求行情、不下单。
- 新增/改变 bind mount 必须使用专用冻结包和 compose 对账；未挂载的仓库修改不会生效。
- backend 重建前保存原 compose、镜像 ID、实际挂载源、应用文件哈希、封印哈希、调度偏好和模拟交易相关集合快照。
- 重建失败按保存的原链回滚；回滚失败请求停止 backend 并保留现场，不删除业务数据。
- 启用后只先做报价 API GET，验证正常股票、ETF 和停牌样本；没有明确订单授权时不创建订单。

## 4. 许可到期

许可到期：2026-11-11 20:00 +08:00。到期前至少一天决定是否续期。续期必须重新核对生产健康、当前许可哈希、备份目录、交易日历和最近失败记录；不能仅把 `expires_at` 改远。若不续期，保持文件原样让代码自然拒绝新来源。

## 5. SSH/转发不稳定时

SSH 管理链路曾出现握手超时、传输截断和回执缺失。应遵循：

1. 先查询已存在的 `status`/reservation/完成收据；
2. 判断是否已经启动过进程；
3. 只对“明确未预留、未运行”的包重新执行；
4. 传输大文件使用已有的分块/标准输入方案，完成后校验 SHA256；
5. 不因一次 TLS 成功就认定上游链路根治；
6. 不修改防火墙、SSH 密钥、证书校验或出口 STOP 来“试通”。

systemd、容器和网络诊断必须用 `safe-inspect.py cmd`，输出只保留状态、错误分类和时间，不回显凭据。

## 6. 回滚触发条件

以下任一条件触发停止并按包内回滚：健康检查失败、实际挂载/镜像/入口漂移、源码或封印哈希不符、许可 owner/mode 不可读、业务快照变化超出批准范围、历史任务偏好变化、报价响应无法证明时间/状态/区间、数据库写入超出预期。

回滚后必须再次确认 backend 健康、原挂载/镜像恢复、Tushare STOP 和历史任务状态未被误改。不要自动删除新产生的业务记录；先保存现场并报告。
