# 大阪机 (`osaka-migration`) 容灾备份与 Cloudflare R2 加密上云指南

> **创建时间**：2026-11-11  
> **适用范围**：甲骨文大阪生产机 (`osaka-migration`) → 腾讯云中转备机 (`VM-0-2-ubuntu`) → Cloudflare R2 独立加密存储桶 (`restic` AES-256)

## 一、大阪机核心资产全景与三级容灾链路

为防范甲骨文云（Oracle Cloud）主机突发停机或失联风险，`TradingAgents-CN` 采用 **“大阪生产机 → 腾讯云本地中转仓 → Cloudflare R2 端到端加密云仓”** 三级容灾架构，确保即便大阪机瞬间彻底失联，也能在 **15 分钟内** 零数据丢失异地拉起全套生产服务。

| 资产分项 | 大阪机源路径 / 产生方式 | 腾讯云落盘路径 (`VM-0-2-ubuntu`) | 同步时间 (CST) | 体量 |
| :--- | :--- | :--- | :--- | :--- |
| **1. MongoDB 全量库 (`k_tradingagents`)**<br>69 张集合（含股票池、分析报告、模拟交易账户/持仓/委托、复盘与记忆库、用户配置及历史行情） | `/usr/local/bin/osaka-backup-mongo`<br>(`osaka-backup-mongo.timer` 每日 04:30) | `/home/backup-recv/osaka/mongo-YYYYMMDD-HHMMSS.archive.gz`<br>+ `.sha256`（保留最近 14 天，`osaka-backup-verify.timer` 每日 06:10 校验） | 每日 `04:30` 推送<br>每日 `06:10` 校验 | 压缩后约 `465 MB`/份 |

## 二、Cloudflare R2 独立存储桶配置步骤（方式 A）

系统已在腾讯云备机配置好全套脚本与定时任务，仅需在 Cloudflare 控制台创建存储桶并填入 3 个连接参数即可激活：

### 1. 在 Cloudflare 控制台创建 R2 存储桶与 API 令牌
1. 登录 Cloudflare Dashboard → 左侧菜单点击 **R2 Object Storage** → **Overview**。
2. 点击 **Create bucket**，输入桶名（建议：`tradingagents-backup`），点击创建。
3. 回到 **R2 Overview** 页面右侧，复制你的 **Account ID**（32 位十六进制字符串），并进入 **Manage R2 API Tokens**。
4. 点击 **Create API token**：
   - **Permissions**：选择 `Object Read & Write`（对象读写）
   - **Specify bucket(s)**：选择 `Apply to specific buckets only` → 勾选刚才新建的 `tradingagents-backup`
5. 创建后页面会显示 **Access Key ID** 与 **Secret Access Key**。

### 2. 在腾讯云服务器填入 R2 凭据
在腾讯云备机 (`VM-0-2-ubuntu`) 终端执行：

```bash
sudo nano /etc/ta-r2/restic.env
```

将文件中的 3 个 `<...>` 占位符替换为你的真实信息（文件中的 `RESTIC_PASSWORD` 已由系统自动生成 256 位高强度随机密钥，**切勿修改**，但**强烈建议将该密码复制一份保存到你个人的密码管理器/备忘录中**，以便极端情况下异地解密恢复）：

```ini
RESTIC_REPOSITORY="s3:https://<你的32位Account_ID>.r2.cloudflarestorage.com/tradingagents-backup"
AWS_ACCESS_KEY_ID="<你的_R2_Access_Key_ID>"
AWS_SECRET_ACCESS_KEY="<你的_R2_Secret_Access_Key>"
RESTIC_PASSWORD="（保留文件内已自动生成的随机强密码，并妥善抄录备份到个人密码库）"
```

### 3. 触发首次上云备份与验证
保存 `/etc/ta-r2/restic.env` 后，直接运行一键备份脚本（首次运行会自动执行 `restic init` 初始化加密仓库并推送全量快照）：

```bash
sudo /home/ubuntu/.local/bin/ta-r2-backup.sh
```

查看云端已归档的加密快照列表：

```bash
sudo bash -c 'source /etc/ta-r2/restic.env && restic snapshots'
```

## 三、日常自动化调度与极端故障恢复速查

### 1. 每日自动化时间表（北京时间 CST）
- **`04:30`**：大阪机 `osaka-backup-mongo.timer` 导出 MongoDB 全量压缩包并推送至腾讯云 `/home/backup-recv/osaka/`。
- **`06:10`**：腾讯云 `osaka-backup-verify.timer` 校验所有归档的 SHA-256 完整性并清理 14 天前旧包。
- **`06:30`**：腾讯云 `ta-r2-backup.timer` 触发 `/home/ubuntu/.local/bin/ta-r2-backup.sh`：
  1. 调用 `/home/ubuntu/.local/bin/ta-pull-osaka-state.py` 拉取大阪机最新非数据库运行态（`osaka-runtime-state-*.tar.gz`）；
  2. 将 `/home/backup-recv/osaka`、`/home/ubuntu/quote-guard-releases`、`/home/ubuntu/系统运维/trading_agents` 及两个 Git 仓库通过 `restic` 客户端 AES-256 加密后增量上传至 Cloudflare R2；
  3. 自动按 `--keep-daily 14 --keep-weekly 8 --keep-monthly 6` 策略修剪云端历史快照。

### 2. 当大阪机突发失联时的异地恢复流程
1. **获取最新数据**：
   - 若腾讯云备机完好：直接使用 `/home/backup-recv/osaka/` 下最新的 `mongo-*.archive.gz` 与 `/home/ubuntu/quote-guard-releases/osaka-state-backups/` 下最新的 `osaka-runtime-state-*.tar.gz`。
   - 若需从 Cloudflare R2 恢复到全新服务器：
     ```bash
     export RESTIC_REPOSITORY="s3:https://<Account_ID>.r2.cloudflarestorage.com/tradingagents-backup"
     export AWS_ACCESS_KEY_ID="<Access_Key_ID>"
     export AWS_SECRET_ACCESS_KEY="<Secret_Access_Key>"
     export RESTIC_PASSWORD="<你保存的_RESTIC_PASSWORD>"
     restic restore latest --target /tmp/ta-restore
     ```
2. **还原运行目录与配置**：
   - 解压 `osaka-runtime-state-*.tar.gz` 恢复 `mounts/app_{config,data,reports,results,uploads}` 与 `app_runtime/`（其中已默认包含 Tushare 历史批次的 `STOP` 门禁文件，防止新机器启动后误触发远端抓取）。
3. **导入 MongoDB 全量数据**：
   ```bash
   docker exec -i <mongo容器名> mongorestore --gzip --archive --drop < mongo-YYYYMMDD-HHMMSS.archive.gz
   ```
4. **启动前后端与 Worker 容器**：按 `meta/running_mounts.jsonl` 与本地生产仓库镜像拉起容器即可无损恢复全部历史报告、模拟盘持仓与分析能力。
