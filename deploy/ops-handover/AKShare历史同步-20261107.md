# AKShare 历史同步交接

## 代码与职责

- `app/worker/akshare_sync_service.py`：股票池、批量/单只同步、失败账本和入口结果。
- `app/services/historical_data_service.py`：历史数据标准化和批量写入确认。
- `deploy/inspect_akshare_history.py`：只读库存、日期覆盖和缺口盘点。
- `app/worker/etf_sync_service.py`：ETF 日线通道；ETF 图表问题与股票历史同步分开处理。

## 已完成修复

- 每只股票的请求、解析和写入错误会保留在结果中。
- 失败股票进入有限重试，不会无限循环。
- 批量写入必须获得明确确认；空标的池、全失败或零写入不能报告成功。
- 不用昨天收盘数据伪造盘中行情，也不把历史日线当成实时成交依据。
- 只读盘点工具不会写库，不改变调度状态。

## 当前数据认识

历史收据曾显示 2026-11-05 最新日约覆盖 5,565/5,577 只、全库约 1,425,909 条。该数字是历史采样，不是永久承诺；需要当前覆盖率时重新盘点。缺少最新日但有更早记录的股票可能停牌、退市或源无行，应记录跳过原因，不能为了覆盖率补一行假数据。

AKShare 财务数据同步目前可单独使用；它与股票历史日线、ETF 日线和 Tushare 财务任务不是同一个调度闸门。修改一个通道前先确认目标 job、写入集合和数据单位。

## 只读盘点示例

使用仓库脚本时把输出写入本机私有证据目录，不把完整数据库文档复制到聊天或 Git：

```bash
cd /home/ubuntu/projects/K-TradingAgents-CN-osaka-safety-20261016
python3 -B deploy/inspect_akshare_history.py --help
# 按脚本帮助指定只读输出路径
```

生产环境命令、容器环境和数据库诊断必须经 `safe-inspect.py` 脱敏；不要直接回显 `.env`、compose、Docker inspect 或 MongoDB 凭据。

## 维护规则

1. 先确认日历和目标日期，再执行增量，不做无关全量重刷。
2. 保存失败股票名单、上游错误分类和写入确认；不能只看 UI 的“任务已提交”。
3. 数据单位必须保持库契约：成交量为手、金额为 CNY；不接受 Tushare 股单位直接写入标准集合。
4. 网络中断时先读任务状态和断点，不要重复点击或新建任务代替续跑。
5. 变更生产前备份相关集合/索引、调度偏好和任务状态，并做回读对账。
