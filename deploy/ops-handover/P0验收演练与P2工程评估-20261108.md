### 2.4 P2.5：`_is_data_fresh` 时区偏差、日线最终性与复权口径评估

- **`_is_data_fresh` 时区与负时间差缺陷剖析（`app/worker/akshare_sync_service.py:326-389`）**：
  1. **缺陷一（BSON Naive UTC 被误判或偏移 8 小时）**：PyMongo 从 MongoDB 读取 BSON `Date` 字段时默认返回 **naive UTC `datetime`**（`tzinfo is None`）。旧代码将所有 `tzinfo is None` 的对象当作“本地时间”与 `datetime.now()` 比较：在 `TZ=Asia/Shanghai` 容器内，刚写入 1 秒的 BSON UTC 时间会被算成“8 小时前”（`minutes=15` 恒为 `False`，导致 15 分钟防抖缓存完全失效）；
  2. **缺陷二（UTC 宿主机上 aware UTC 被 `+8h` 产生负差值）**：旧代码对 `tzinfo == timezone.utc` 手工 `+8 小时` 并抹去 `tzinfo`，若进程时区为 UTC，则 `now - updated_at` 为 `-8 小时 < 15 分钟`，导致旧数据被恒判为“新鲜”；
  3. **缺陷三（未来时间戳未拦截）**：`time_diff.total_seconds() < minutes * 60` 未检查下界，任何负数（未来时间）均返回 `True`。
- **统一修复方案（已在 `TestP25FreshnessTimezoneAndFinality` 验证通过）**：
  - 直接复用 `app.services.quote_contract` 中的 `parse_quote_time`、`cn_now` 与 `DEFAULT_MAX_FUTURE_SECONDS`（`60s`）：
    ```python
    parsed = parse_quote_time(updated_at)
    if parsed is None:
        return False
    age_seconds = (cn_now() - parsed).total_seconds()
    if age_seconds < -DEFAULT_MAX_FUTURE_SECONDS:
        return False
    return age_seconds < threshold_seconds
    ```
- **日线最终性与复权口径边界结论**：
  - `stock_daily_quotes`（AKShare 同步）为**前复权（`qfq`）**口径且不含 `is_final` / `trading_status`；`stock_daily_quotes_unadjusted`（Tushare 基础档同步）为**未复权**口径；`etf_daily_quotes` 为不复权日线但同样不含 `is_final` / `trading_status`。
